# Лабораторная работа №4. План автоматизированного тестирования

## Цель тестирования

Цель тестирования JobAbility — в первую очередь защищать сценарии, ошибка в
которых нарушит бизнес-процесс или безопасность приложения. Поэтому план
покрытия построен по приоритету и риску, а не по списку моделей.

Основные риски приложения:

- пользователь получает действие, недоступное его роли;
- вакансия публикуется без модерации;
- заявка формируется с неверными данными или неверной суммой;
- важные пользовательские пути перестают работать после изменений.

Полное покрытие всего кода не является целью лабораторной. Цель — покрыть
наиболее значимые сценарии и показать обоснованный план дальнейшего развития
набора тестов.

## Тестовая среда

Тесты запускаются с отдельными настройками:

```powershell
python manage.py test core --settings=config.test_settings
```

В `config.test_settings` используется in-memory SQLite, локальный кэш и
локальное файловое хранилище. Тесты не используют основную PostgreSQL-БД и
MinIO, поэтому создаваемые тестовые данные не затрагивают рабочие данные.

## Виды и теги тестов

**Unit-тест** проверяет отдельную функцию без API и без БД. Такие тесты быстрые
и удобны для проверки валидных, невалидных и граничных значений.

**Integration-тест** проверяет взаимодействие REST API, бизнес-логики и БД:
создание объектов, изменение статусов и сохранение результатов.

**Smoke-тест** — короткая проверка того, что главный успешный путь приложения
работает в принципе. Он отвечает на вопрос: «система после изменений вообще
способна выполнить основной пользовательский сценарий?».

**Regression-тест** фиксирует ожидаемое поведение, которое нельзя потерять при
следующих изменениях. В данном наборе это особенно важные запреты: обычный
пользователь не может создать вакансию, а пустую заявку нельзя сформировать.

**Permissions-тест** целенаправленно проверяет разграничение доступа по ролям.

**Business logic-тест** проверяет правила предметной области и граничные
значения, например обработку дат и безопасных имен файлов.

| Тег             | Что реально входит сейчас                                                     | Зачем запускать                                                       |
| ------------------ | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `unit`           | 8 тестов `parse_date` и `transliterate_to_latin`                                         | Быстрая проверка функций без БД                          |
| `business_logic` | 8 unit-тестов и запрет формирования пустой заявки              | Проверка граничных данных и бизнес-валидации |
| `integration`    | 1 счастливый путь и 2 негативных сценария через API/БД      | Проверка связанной работы системы                     |
| `smoke`          | 1 полный счастливый путь формирования заявки                  | Быстро убедиться, что основной процесс жив      |
| `regression`     | 2 негативных сценария, запрещающие неверное поведение | Не допустить возврата опасных ошибок                |
| `permissions`    | Запрет соискателю создавать вакансию                               | Проверка разграничения прав по ролям                |

Команды запуска:

```powershell
python manage.py test core --tag unit --settings=config.test_settings
python manage.py test core --tag integration --settings=config.test_settings
python manage.py test core --tag smoke --settings=config.test_settings
python manage.py test core --tag regression --settings=config.test_settings
python manage.py test core --tag permissions --settings=config.test_settings
python manage.py test core --tag business_logic --settings=config.test_settings
```

## Реализованное покрытие

### Unit: обработка граничных данных

В `core/tests/test_unit_services.py` реализованы проверки:

- корректная ISO-дата разбирается;
- пустая дата обрабатывается без ошибки;
- неверный формат даты отклоняется;
- проверяется граница високосного года;
- русское название преобразуется в безопасный slug;
- латиница и цифры сохраняются;
- пустое или состоящее из символов имя получает безопасный fallback.

Эти тесты важны, потому что некорректная дата меняет результаты фильтрации, а
некорректное имя файла может нарушить загрузку медиа вакансии.

### Integration и Smoke: главный успешный путь

В `core/tests/test_integration_application_flow.py` реализован сценарий:

1. Работодатель создает вакансию.
2. Вакансия сохраняется как `PENDING` и не активна.
3. Модератор одобряет вакансию.
4. Вакансия становится `APPROVED` и активной.
5. Соискатель добавляет ее в черновик с количеством `2`.
6. Соискатель заполняет заявку.
7. Заявка переводится в `FORMED`.
8. Проверяется итоговая сумма `240000`, дата формирования и ожидаемая дата ответа.

Это одновременно integration-тест и smoke-тест: он взаимодействует с API и
тестовой БД, а также подтверждает работоспособность основного пути приложения.

### Integration и Regression: защитные сценарии

Реализованы проверки:

- соискатель получает `403` при попытке создать вакансию, а запись в БД не
  появляется;
- пустой черновик получает `400` при попытке формирования и остается в статусе
  `DRAFT`.

Это regression-тесты, потому что они закрепляют критичные ограничения системы.
Если дальнейшее изменение API случайно ослабит проверку роли или валидацию
заявки, эти тесты сразу покажут регрессию.

## План покрытия по приоритету

### Приоритет P0: критично, проверять в первую очередь

Риск: нарушение прав доступа, публикация непроверенной вакансии или потеря
корректности главного пользовательского процесса.

| Сценарий                                                                                                        | Почему критичен                                                                                 | Тип теста                    | Состояние       |
| ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ------------------------ |
| Полный путь: создание вакансии → модерация → формирование заявки | Главный бизнес-процесс, несколько ролей и изменение данных  | Integration, Smoke                   | Реализован     |
| Соискатель не может создать вакансию                                                    | Нарушение роли позволяет публиковать чужие данные                 | Integration, Regression, Permissions | Реализован     |
| Нельзя сформировать пустую заявку                                                         | Недопустимая заявка попадает в обработку                                  | Integration, Regression              | Реализован     |
| Модерацию вакансии выполняет только модератор                                  | Иначе вакансия может быть опубликована без контроля              | Integration, Permissions, Regression | Запланирован |
| Публично видны только `APPROVED` и активные вакансии                              | Иначе показываются отклоненные или непроверенные вакансии | Integration, Regression              | Запланирован |
| Нельзя получить или изменить чужую заявку                                           | Риск утечки и подмены данных соискателя                                     | Integration, Permissions, Regression | Запланирован |

Запускать: при каждом изменении авторизации, статусов, API вакансий или заявок;
обязательно перед сдачей.

### Приоритет P1: высокий

Риск: некорректная сумма, нарушение жизненного цикла заявки или сбой входа
пользователя.

| Сценарий                                                                                        | Почему важен                                                                                                             | Тип теста             | Состояние                                        |
| ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- | --------------------------------------------------------- |
| Пересчет `total_salary` при нескольких позициях и количестве  | Сумма относится к ключевым данным заявки                                                         | Unit, Integration, Regression | Частично покрыт в happy path               |
| Запрет недопустимых переходов статусов заявки                  | Сформированную/завершенную заявку нельзя вернуть в неверное состояние | Unit, Integration, Regression | Запланирован                                  |
| Модерация сформированной заявки: finish/reject                             | Завершает основной жизненный цикл заявки                                                        | Integration                   | Запланирован                                  |
| Регистрация и вход для допустимых ролей                               | Без авторизации невозможно использовать кабинеты                                        | Integration, Smoke            | Запланирован                                  |
| Неверные данные входа и смены пароля                                     | Защита учетной записи                                                                                            | Integration, Regression       | Запланирован                                  |
| Обязательные данные профиля перед формированием заявки | Неполная заявка не должна уходить работодателю                                             | Integration, Regression       | Частично покрыт пустой заявкой |

Запускать: перед merge и перед демонстрацией; для затронутого модуля — сразу
после изменений.

### Приоритет P2: средний

Риск: ухудшение пользовательского опыта или локальные ошибки данных без
нарушения основного процесса.

| Сценарий                                                                        | Почему нужен                                                                        | Тип теста       | Состояние                                                                               |
| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------ |
| Фильтрация вакансий по строке, зарплате и датам | Пользователь должен находить релевантные вакансии | Unit, Integration       | Unit-парсинг даты реализован, API-фильтры запланированы |
| Добавление одной вакансии повторно                       | Не должны создаваться дубли строк заявки                    | Integration, Regression | Запланирован                                                                         |
| Изменение и удаление строки черновика                  | Влияет на содержимое и сумму заявки                              | Integration             | Запланирован                                                                         |
| Обновление профиля соискателя                                | Нужны корректные данные в заявке                                   | Integration             | Запланирован                                                                         |
| Транслитерация/путь загружаемого файла               | Защищает работу с медиа                                                    | Unit                    | Реализован                                                                             |
| Кэш списка вакансий и его инвалидация                   | Пользователь не должен видеть устаревшие данные      | Unit, Integration       | Запланирован                                                                         |

Запускать: при изменениях фильтров, профиля, корзины, кэша или медиа.

### Приоритет P3: отложенный и инфраструктурный

Риск ниже для требований текущей лабораторной либо требует отдельной среды.

| Сценарий                                      | Причина более низкого приоритета                                                                                                                         | Тип теста    | Состояние       |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ------------------------ |
| Реальное хранение медиа в MinIO | Нужны контейнеры и настройка S3                                                                                                                              | Integration/E2E      | Запланирован |
| Работа с реальной PostgreSQL           | Для основной логики достаточно изолированной тестовой БД; отдельно нужно проверять совместимость | Integration          | Запланирован |
| React UI, Redux и навигация                 | Требуют frontend test runner или браузерных e2e-тестов                                                                                                      | Component/E2E        | Запланирован |
| Prometheus и Grafana                                 | Мониторинг, а не центральный бизнес-сценарий                                                                                                    | Smoke/Infrastructure | Запланирован |
| Django HTML-шаблоны                            | Основной объект проверки лабораторной — REST API                                                                                                   | Integration/E2E      | Запланирован |

Запускать: перед релизом или после изменений инфраструктуры и интерфейса.

## Стратегия запуска

При обычной разработке backend:

```powershell
python manage.py test core --tag unit --settings=config.test_settings
```

После изменения прав, API, статусов или расчета заявки:

```powershell
python manage.py test core --tag integration --settings=config.test_settings
python manage.py test core --tag regression --settings=config.test_settings
```

Для быстрой проверки главного пути:

```powershell
python manage.py test core --tag smoke --settings=config.test_settings
```
